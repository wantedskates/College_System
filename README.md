# College system

A user-friendly web and mobile application in which everything related to college can effectively and easily be finished digitally without any on-site presence in college at all, i.e, fully digitalizing anything that could be digitalized in college. The system should be deployed as a mobile app and a web application and a static marketing explanatory website for the college. Should the mobile app be accessed by all actors ? Are there some areas in the app in which it is only allowed for specific family of actors to access? What are the differences between the mobile and web app? Who should use the mobile app and who should use the web app? Could the mobile app be offline-friendly? Could the mobile app be linked with other external services ? ( making a deal with Uber or Didi to integrate there service for students in the app or just like AAST collaborated with Kortex to provide an E-learning platform ). 

## Actors 
Those are the distinct agents that interact with the system and each group is further divided into other sub-groups and those are too divided in other sub-groups and so on till the atomic elements are reached (a single individual) and each atomic element has its own user interface. For each atomic element there is a group of functions that he does, those functions for all groups must be defined precisely  before the architecture design (e.x a student wanting to see his results or an instructor sending a message to a student ). Those functions then are too grouped into families. 

Each atomic element (user) has a unique interface and in his interface there are different digital areas each one encapsulating a group of related function and the user has unlimited access to those services. 


They actors of the system are :- 
1. Students
2. Instructors
3. Administration
4. Employees 
5. Outsourced employees
6. Guests
7. Special others


## Artificial entities 
Those are entities that are abstract such as College or Course. They have a tree-like hierarchy.
